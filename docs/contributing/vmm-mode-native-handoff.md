# Native VMM mode handoff

The writable direct VMM path retains the original read-only sidecar open file description and one anonymous final-boundary pipe. The concrete jail command owns them. They are private purpose capabilities, outside ordinary file grants. A setup version or descriptor number cannot create a native source.

The host retains the command's atomic creation pidfd before it sends setup. Each fixed helper creator reports its actual child creation pidfd while that child is blocked on setup. The original receiver checks the current kernel sender, code, anchored task birth and namespaces before acknowledging that creation. The init closes ordinary file and mount capabilities before releasing its child. The three exact private mode capabilities last only until the creator reaches its fixed wait path.

Private slots follow the existing file, setup, status and pin slots. The outer mapping pipe follows the actual inherited vector, including those private slots. The final trusted runner remaps only the checked private capabilities. It refuses unknown occupied targets. It does not overwrite a Go runtime descriptor or add a general close-on-exec exception.

The last helper completes every read-only reopen and offset isolation while the VMM remains mode `0555`. Its bounded pipe record is data. The host must also own the original creation, code, namespace and source proofs before it arms the same mode lease. The armed helper sets only its private lease and pipe writer close-on-exec immediately before its one external exec. The Go file owners remain live through that syscall.

EOF is insufficient. The host also checks the same still-live final creation and its current executable against the original VMM object. A helper error or early close retains uncertainty. A successful final exec restores mode `0555` and ends the mode fence. The VMM's ordinary physical lifetime continues separately.

Physical cleanup checks the original command and namespace-init creation descriptors independently. It does so before normal wait is consumed or resources are closed. An uncertain source remains retryable through the same command. Cancellation uses the original descriptors and a cleanup context; cancellation itself grants no closure permission.

The host-user-namespace outer route, the full slot cojoin and native fixtures remain open. This source does not establish availability. Missing native code or namespace access refuses the direct path. Memory protection, generic file policy and the strict sealed fallback remain unchanged.
