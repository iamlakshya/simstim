# Fixed controller production route

The original host factory checks its accepted boot receipt, current session
operation, signed runtime suite and captured mount plan. It retains the guest
stream outside the native command. The mapped helper receives only public
native setup objects.

The final controller vector has these fixed roles:

| Descriptor | Role |
| --- | --- |
| 0–2 | Read/write null devices |
| 3 | Original setup-only Unix stream |
| 4 | Sealed typed controller state |
| 5 | Sealed public topology |
| 6 onwards | Same original native mount and state objects |
| Next, for guest init | Same original fixed helper code |
| Final five | Proc umounter, runsc, Sentry, FD parking, prewarmer |

The outside constructor supplies no agent command, environment, private
operation or guest stream in this vector. The one-ID self-map and empty group
contract remain in place. C inherits the safe mount graph and bounded setup
capabilities. Its writer measures the actual native objects and current root,
seals the exact controller, base and boot records, installs only the reserved
state slot and closes other aliases across exec. The program is the same held
static runsc, with one fixed internal argument vector and environment.

A retains C's original atomic creation pidfd through reaping. It transfers that
same creation source over its original post-map channel before C receives its
setup. The outside command keeps its own reference and requires positive exit
from every original creator, including C. Unknown creation or wait results keep
the original owner and resources.

The controller constructs its two filesystem roles from the same signed code
suite. The Sentry keeps its same-process final re-exec and raw pre-Go filesystem
restriction. Controller and Gofer use the existing all-thread filesystem-only
branch and keep their common scoped ancestor. The controller joins each exact
child creation, current witness, final filesystem result, tiny-child exit and
parked Gofer vector before its own final filesystem result and aggregate.

The outside consumer checks C's current kernel sender and creation handle,
held code and actual command vector, stable task birth, native namespace kinds,
owners and parent relationships, and the exact fresh socket. It checks the
same objects again after the filesystem result and aggregate. Failed native
code or namespace observations refuse the transfer. No failed observation,
PID, role field, copied receipt, setup EOF or timeout supplies permission.

The original session wrapper enters its same operation's current-read guard.
It checks the original boot receipt and code suite again, then lends only its
original withheld guest stream through the authenticated fresh endpoint. The
physical probe uses its own same-request guard. The private operation remains
outside. The loan is one-use even when the send fails. The fixed controller
then releases the original IO vectors and starts the fixed root. The ordinary
guest hello and private agent plan continue on that same byte stream.

The outside copy of the public child setup endpoint closes after A has its
kernel copy. This allows C's later setup EOF to describe that transport. Code,
guest and native lifetime sources remain retained. Native cancellation signals
original pidfds and joins real processes. Cleanup publishes physical exit
before retiring the controller owner, with consistent mutex order. Other
private execution purposes remain separate.

The exact runtime patch, five-role table, build inputs, release producer and
all consumers must migrate together. Source and test compilation do not prove
native memory privacy, ptrace ancestry, namespace observation, whole-process
cleanup, race freedom, resource bounds or hardware availability. Those gates
must pass under the original runtime and host operation before availability
is accepted.
