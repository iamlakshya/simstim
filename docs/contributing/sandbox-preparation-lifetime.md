# Fixed sandbox preparation lifetime

The fixed test boot uses the original authenticated bridge, reserved session
directory and primary operation. Its private purpose is issued by the actual
outside operation and accepted with the original native loan. A manifest label
cannot issue that purpose.

The RPC result has a 60-second deadline. On cancellation or expiry it sends one
failure, stating that physical cleanup is unconfirmed. The same request worker
keeps the original operation, reservation, launch and artifact receipts until
cleanup joins. The bridge registers that worker before starting it. Closing the
connection cancels construction, then waits for the worker before closing its
receipts. Process shutdown also waits beyond the normal request drain. No
replacement cleanup worker, permanent keeper or listener is created.

Only fixed preparation keeps the borrowed operation after readiness. Its original
control reader remains active until cancellation or parent EOF. A fixed command
can finish before the parent reads readiness; the supervisor still retains the
same control reader and native owners until that parent sends cancellation or
leaves. Ordinary sessions keep their existing readiness and EOF behaviour.

The original outside prepare reader has a bounded incremental frame cursor.
Only read deadlines preserve its partial header, body, native descriptors and
current sender. It never replays a prefix through a new decoder. Its original
pending request IDs are a closed set: 1, 2, 3 and 5. Cancellation is request 4.
The supervisor fails a registered unfinished readiness response before its final
cancel acknowledgement. Unknown responses, another sender, malformed or extra
rights, peer EOF and a missing acknowledgement fail closed. The existing one and
three descriptor bounds are unchanged.

The supervisor kills and joins the same actual runtime, then calls that runtime's
owned `Destroy`. A nonzero exit caused by its requested stop remains a diagnostic.
It is separate from positive physical cleanup. Failed destruction keeps the same
runtime and borrowed operation in the existing cleanup stack. All other cleanup,
borrowed operation closure and holder closure must succeed before the native
acknowledgement. The outside owner then joins the original supervisor's native
exit. Its same native manager must report the exact unit absent, and the native
canonical cgroup must also be absent. An inactive or failed unit, main-process
exit, EOF or saved status supplies no whole-unit proof. The outside owner never
stops an unknown replacement invocation.

Final directory cleanup atomically claims the exact original reservation. It
walks anchored original directories and checks native identity, ownership,
links and mount identity. Unknown external socket or legacy runtime paths are
preserved. The terminal operation name is also claimed and checked against its
retained descriptor. A new reservation at an old public name is left alone.

The test sources cover byte-cut deadlines, native descriptor and sender
continuity, queued replies, actual process SIGKILL and destruction, and original
directory replacement. Full boot, cancellation, parent death and every concrete
backend still require their real native and end-to-end checks. Source structure
or transport-only fixtures do not qualify the complete preparation path.

The supervisor adopts the accepted operation before checking any later error.
It captures the placement cleanup token and native parent cleanup anchors before
calling a runtime factory. Partial runtime, disk and capture owners stay on that
same stack after a constructor fails.

After cancellation, the original control reader settles queued replies. The same
runtime must finish `Destroy`, and disk, capture, agent and publication cleanup
must finish before the borrowed operation and holder close. Only then may the
original control line acknowledge cancellation. Native close errors stay errors
on later calls. A read deadline preserves the original frame prefix; EOF and a
changed sender cannot restart the decoder.

If the outside parent disappears, the captured original pidfd must positively
report its exit. The supervisor then removes only its anchored original directory,
after all runtime resources have joined. A live parent retains responsibility
for that directory. A moved parent, replaced directory, extra link or uncertain
unlink leaves the original owners retained. The 60-second RPC deadline reports
failure once and does not bound physical cleanup.
