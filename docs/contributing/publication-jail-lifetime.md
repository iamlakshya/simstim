# Converter publication lifetime

The original unstarted converter command retains its guardian's same private read-only shared-lock open description. The private suffix follows captured files and pins. It is separate from ordinary inherited files and file rules. Only the closed publication init and exec stages accept its setup metadata; generic or foreign stages refuse it.

The command keeps its parent copy through an uncertain start and actual native lifetime. The init stage duplicates that same open description before generic inherited wrappers close. It keeps the duplicate on every success and error path. Its deferred descendant reap runs before that duplicate closes. A later converter inherits the same original description.

Immediately before the single intended external exec, the fixed converter role reserves its raw fence descriptor and installs the pre-exec restrictions. The dedicated converter entry verifies that descriptor before parsing and installs the final all-thread restriction on later exec. Ordinary jail profiles and file rules keep their existing behaviour.

The hooks cover the existing direct login converter identity. They add no subordinate-ID, generic outer or userspace-kernel purpose. A fresh different open description must acquire an exclusive lock before publication cleanup. EOF, a phase field, manager response or parent death does not prove writer closure.

The complete native execution issuer and publication producer cohorts must be composed with these hooks. Source joins do not establish original scope, cancellation, parent-death, lock vacancy or hardware acceptance.
