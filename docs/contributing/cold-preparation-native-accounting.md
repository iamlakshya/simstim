# Original cold preparation lifetime

The real bridge preparation creates the reservation through its same original operation, native cold source and existing publication record. The locked kernel checks that actual record, the current boot and complete cap. A nonce, saved row, private-context claim or host fact cannot issue the lease.

The reservation remains while keys are fetched and while Starting is published. The restart writer reuses the actual native holder vacancy, refreshes Starting inside the placement transaction and counts its own held quantum once. Native dispatch uses the same current control record and fresh room; it does not reopen another holder or add the reservation again.

The actual private operation sender settles the leaf only after the new creation, code, current sender, unit cap, zero swap, membership and original disk source have been verified. The same native unit then continuously owns the complete charge. Starting, a unit name or an acknowledgement cannot settle it.

Cancellation joins actual work through the original cold source before removing its own leaf. It can use an independent cleanup context after connection cancellation. A closed cleanup path may finish its same reservation while purge drains the host; it authorises no new start, stop target or other publication. Any native, inode or final-write uncertainty retains the actual original owner and charge. Ordinary Run and Life are untouched by the reservation writer.

Native cancellation, creation, failed handoff, concurrent room and crash tests remain required. Source compilation alone does not establish resume availability.
