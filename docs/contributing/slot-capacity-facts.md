# Advisory slot counts

Host facts read the root allocator's existing derived projection in process. The reader checks the actual caller UID, current boot, native root ownership, strict bounded format and freshness. Missing, stale or uncertain data leaves the optional slot capacity observation absent. Facts run no sudo command, subprocess, probe or allocation.

Known observations describe a fixed pool of sixteen slot leases. Occupied, free and quarantined form its complete partition. Occupied does not mean a running whole VM. The timestamp and generation are observation data, and the client keeps its own accepted-source receipt time.

The observation cannot choose an own-account label, reserve a slot or permit a boot. The actual protected VM Need and native source decide mode; the root allocator freshly enforces the seventeenth no-room result. Existing memory admission remains fresh and atomic.
