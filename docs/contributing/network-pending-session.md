# Session rules from pending requests

The outside request carries only the original session, opaque request ID, revision, scope and restrictive address maximum. The supervisor checks that session before choosing its actual current root egress process. It forwards the whole declaration unchanged.

The target comes only from that same egress control response after its source-aware writer has completed a non-sensitive public snapshot. A display row or caller-supplied target cannot enter this route. The supervisor checks the exact request, revision, scope, expiry and single endpoint representation again.

A session answer holds the existing policy turn. It installs the rule through the current egress source and checks its source hash, then saves through the same manifest journal and publishes the result. A changed actor, layer vector, pending capsule or expired request fails the write and disarms the live policy service. Numeric targets keep the public-address restriction.

Repository and profile answers return the transient public snapshot. The original client still owns the local permission, source checks and file write. Sensitive targets use the separate protected-memory path and cannot be published by this route.

A once answer or sensitive session answer returns only one opaque protected-memory grant ID. A non-sensitive session answer first completes the same durable writer and returns no target on its answer channel. The original actor must remain the same across the explicit publication handoff.
