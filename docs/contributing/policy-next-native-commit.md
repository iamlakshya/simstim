# Applying pending policy metadata

A pending laptop policy capsule is source data. It cannot select a new native image, grant secrets, create a startup, or prove that its values were applied. Excluded session and builtin sources always come from the current protected record.

The original native startup captures the capsule under its accepted operation. Only after real readiness on the same physical connection may its outside owner request a metadata commit. The actual supervisor checks its native holder, generation, original Need and runtime, current sender and unchanged captured capsule.

The pure matcher compares the exact selected laptop projection from the actual protected applied layers. Missing, future, malformed or mismatched inputs stay pending. A hash or public readiness flag cannot replace native ownership.

The same supervisor save turn clears the capsule and updates its live copy after durable success. An old tick therefore cannot put it back. The outside owner retains the original operation through this acknowledgement and rereads the protected result. Ordinary run, lifecycle, current policy, secret state and native selection are preserved.

Native startup, publication errors, cancellation and race tests remain required.
