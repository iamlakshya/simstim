# Native resume inspection

Resume preparation keeps the original primary operation and its protected root. It returns one opaque warm or cold source. A row, PID, saved unit name or failed socket connection cannot construct either source.

A warm source retains the current native controller, its code and namespace descriptors, its current socket sender, its actual native unit and cgroup, and its exclusive holder description. The controller checks the same original runtime owner and connection again before and after an agent resume. Process runtimes retain their original native copy owner. Gvisor retains its original sandbox, accepted hello, Start connection, signed runtime and native creator chain. A copied factory state or reopened path cannot renew that source. A warm resume carries no new named SSH keys. A failed warm check cannot turn into a cold start.

A cold source retains actual native absence and the checked saved image, agents, runtime and disk descriptors under the same operation. Checking the proposed manifest keeps this source locked until the complete original Need and runtime have been compared. Fresh memory admission and a new original native startup remain separate requirements.

The initial cold implementation covers a saved login-owned microvm after a genuine change of host boot. A missing current-boot controller remains an error. These cases must retain their files until their original native owner can settle them. The scope does not treat a timeout, EOF, `starting` state or ledger entry as physical closure.

The borrowed startup operation closes after the actual ready commit. A warm check retains the accepted immutable boot receipt and actual holder instead of trying to reload through that closed startup operation. The outside request still holds its own original primary operation and current native controller proof.

The ordinary connection changes reader only at the empty boundary of its explicit native inspection. The fixed warm lane then accepts the connector's actual code and namespace descriptors and borrows its original operation description. The kernel keeps that same operation locked through worker cleanup, including a parent process death. Ordinary attachment readers and descriptor limits stay unchanged.

Cancellation has a fixed request and an explicit joined acknowledgement. The native worker finishes its tracked cleanup before the reply. Release closes the borrowed operation only after that join. A timeout or EOF never proves cleanup. A lost release reply or an uncertain member mutation preserves the original source until independent whole-unit closure; it cannot turn into a cold retry.

A failed cold startup keeps its original creation descriptor through cancellation. Its accounting can clear only after the tracked creation and both ordinary and auxiliary native unit and cgroup lifetimes have ended, followed by a new real holder vacancy. A ready runtime keeps its continuous native capacity owner.

These operations are private helper operations. They do not change terminal bytes or create a network listener.
