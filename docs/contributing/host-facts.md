# Host facts and admission

The version 1 `host.facts` request takes an empty object. It observes the current helper's native host identity. It acquires the existing control and placement locks, checks the same native state-domain binding, and reads the same reservation scan used by admission. It creates no session operation, reservation or runtime receipt. It runs no probe, provider, namespace or VM.

A current-boot primary with a native canonical unit reserves its complete declared cap when walled. A starting primary without a unit counts for two minutes. A child with `SandboxOf` adds nothing. A session without a wall contributes its actual native memory usage. An unresponsive holder socket changes none of these rules. A canonical unit without a readable protected reservation makes accounting unknown. A native scan also catches a unit whose entire reservation directory is absent.

Facts report the host budget, reserved bytes and their exact difference. Room may be negative when existing reservations exceed a changed budget. Unknown accounting has a false known bit and no selectable room. An observed zero remains distinct from an unavailable read. The response's health rows explain unavailable accounting.

Pressure is Linux PSI `some` `avg10`, as a percentage. Disk free is the space available to this user. Battery state comes from native power-supply status. Each optional measurement has its own known bit. Missing evidence never becomes a healthy zero.

Wall facts come from the existing cache and its native publisher receipt, bound to the current boot and mapped helper. Runtime digests are plain lower-case SHA-256 item digests with the existing cheap size and mode presence check. Image digests use `sha256:` and name the checked cache records. Both lists are advisory metadata. They issue no permission and prove no executable bytes or physical readiness. The observer opens both stores without creating roots, bindings, sentinels or leases.

The client records when it received facts on the same accepted source, host ID and boot. A remote timestamp does not extend freshness. A selected host must still admit the actual new request under the placement lock. Facts never replace that fresh check or the original signed runtime delivery and physical probe.

The client rechecks the current saved host entry, its generation and original Source before and after each facts reply. Keeping a generation marker does not conceal a changed entry.
