# Native slot runtime adapter

An optional installed root launcher can supply a separate native source for a microvm. Its slot inventory and public root-step history describe availability. They cannot create a VM binding or replace the original protected operation and Need.

A new preparation records its chosen disk identity mode once. Existing login and subordinate-ID disks retain their original mode. A saved own-account mode requires the current optional native producer. Enabling the optional route never migrates an existing disk or substitutes a fresh root-owned disk.

The engine retains its actual source, keeper and init process handles, native cgroup, original runtime and disk descriptors and exact guest connection. Its private concrete slot proof joins the existing runner control and native binding interfaces. The ordinary received-VMM proof remains separate and unchanged. No slot number, PID, root UID, inventory row or successful callback creates that proof.

Boot compatibility evidence separates identity modes and requires this actual engine's native source. Destruction uses the same concrete optional native owner and keeps existing physical lifetime guards. These source joins need the root launcher's complete native validation and do not claim native execution, confinement or hardware acceptance.
