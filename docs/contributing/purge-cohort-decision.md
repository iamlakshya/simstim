# One native decision for purge

Every prepared native monitor in a removal must observe one common decision. If each monitor decides on its own when the client disappears, one subject can kill while another thaws. A status row or an in-memory commit flag cannot coordinate separate processes after their owner dies.

The original transaction creates one private Unix sequenced-packet socketpair. Every genuine monitor receives duplicates of the same native receiver and sender. The original socket objects, type, domain and kernel cookies remain checked. A stored name, file descriptor number or report cannot recreate the pair.

Commit and abort use fixed one-byte packets. The first packet queued by the kernel decides the cohort. Every observer peeks at it without consuming it. Later proposals cannot replace that first decision. A full queue still leaves its first packet observable. Unknown or malformed state preserves the original objects; it does not default to either action.

An expiry, cancellation or owner death proposes abort, then observes that same first packet. A commit which already won stays committed. Only a genuine global permit may propose commit after every actual monitor and current copy is ready, every final work-loss check passes and every auxiliary reader physically joins. The permit must bind the original operation, root and source objects. Data, a callback or a phase cannot issue it.

The native file projection is a resource loan only. It carries no runtime, stopped subject or cleanup authority. Its actual factory still has to bind the same original operation and native monitor before sending the descriptors.

The socketpair and original loans stay reachable through all monitor joins. No process consumes or clears the first decision. The pair closes only after all genuine monitor loans return. Native race and coordinator-death tests are required before activation; source and compiler checks alone do not establish this guarantee.
