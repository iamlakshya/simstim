# Native slot snapshot custody

A slot snapshot starts on the same accepted native warm-resume connection. The outside factory checks the original operation, holder, supervisor invocation, protected VM Need and runtime before retaining its native objects. Public request data and descriptor counts cannot issue this owner.

Legacy custody retains running and selected read access. Reserved custody has its own exact request and descriptor layout. It also retains the original exclusive allocation lease from the actual keeper. Receiving that lease observes its existing kernel lock; it never acquires or unlocks it.

The outside owner keeps the original supervisor pidfd, cgroup, code and namespace handles independently. It preserves partially received resources on errors. Closing first cancels and joins its actual root operations. A failed close remains an error on the same owner.

Selection runs the actual clone and space probes before stopping. Its disk and metadata are separate read owners. They retain their original file identities and use the fixed root read check after the running owner closes. They grant no current-disk replacement or stop permission.

Stopped replacement additionally needs the same actual whole-stop owner, positive original actor exits, native cgroup vacancy and the continuously held original allocation lease. Ordinary stop keeps its fresh-lock checks. The reserved root stop, replacement and new keeper handoff remain separate lifecycle consumers; a lost acknowledgement or an ended pipe proves none of them.

The stopped backend consumes that same whole-stop capture and lease. Its prepared restore keeps the original native roles, selected read caps and actual replacement file. Prepare, exchange, rollback and finalisation each use their fixed native layouts. The actual root creator checks the named inodes and reports the physical disk phase before a later sync or acknowledgement can fail. Journal fields describe that progress; they cannot recreate a prepared owner.

A refused close leaves the same prepared cleanup lifetime usable. Partial construction remains reachable, and a fresh stopped borrow cannot race the outside owner's close fence. The reserved cold-start consumer must keep the same lease until the actual new keeper receives it.

The slot cold delegate retains its own actual old native operands and allocation lease. It uses the existing genuine boot and image producers for the current protected Need. Local VM artifacts keep their actual private `vm` parent root and use the fixed `disk.img` leaf; slot artifacts use their original root-issued disk handle.

Reserved startup has a separate nineteen-role receiver on the actual new creation's startup line. It accepts the original operation and eighteen reserved operands only after the native candidate and exact preparation match. A partial operation owns those rights before later validation. The actual original boot receipt lends its old operands once to the fixed new root creator. The new native VM binding must independently observe the same lease before the old local operand copies retire.

After ready, the outside owner captures a fresh genuine warm controller and its actual new reserved source. It matches that source to the retained original new creation and native unit, and compares the two real lease descriptions. A ready acknowledgement cannot release the old outside reservation. Cleanup retains partial objects and leaves refused cleanup callable.

A failed new slot creation has its own retry receipt. It retains that actual creation pidfd, live-captured whole unit, same operation and continuous original lease. A positive failed-unit closure can transfer a fresh holder vacancy and accounting to another actual cold attempt. It cannot reactivate the old stopped receipt or reset one-use secret delivery.

The fixed root abandonment operation settles the failed allocation using its actual creator and unit capabilities while preserving the same exclusive reservation. The next attempt retains the actual current disk, including a genuinely finalised replacement. Failed abandonment, partial artifacts and uncertain native closure remain owned until cleanup or a supported native proof finishes.
