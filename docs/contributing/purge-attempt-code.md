# Temporary purge code factory

The code factory runs before any purge operation or native session capture. It derives its copy from the actual outside helper's retained mapped executable descriptor. It checks the current original placement, host identity and root scope. A path, digest, file-info value or saved temporary directory cannot construct it.

The factory exclusively creates one private directory outside every removable product root. It owns that directory, its original locked file description and its newly created executable inode. The copied bytes are compared directly against the original descriptors, within a fixed bound, with native metadata checks before and after. The factory opens its read-only code descriptor before sealing the named image to execute-only mode.

A native bootstrap loan contains only public code descriptors and the actual running creator's self-pidfd. These are not primary operations, session subjects or permission to stop anything. The later real execution producer must bind them to its original atomic child creation before any private custody is sent. An environment value or inherited descriptor number selects a bootstrap role only.

Closing the factory prevents future borrowing and refuses release while an actual loan remains. Cleanup uses the same retained creator descriptors, captures original names without replacement, rechecks native identity and removes only its own files and empty directory. A replacement or unrelated entry is preserved. Partial cleanup retains the same actual objects for retry.

The raw child entry, original parent and copied-child native authentication, placement admission, actual attempt transaction and post-stop continuation are separate work. Default executable and native hello checks stay unchanged. This factory alone cannot run purge, produce a stopped subject or promise retry after helper deletion. Source tests cover native byte comparison and replacement preservation; complete native startup and `ND0` acceptance remain unproved.

Construction can return both its actual unsealed owner and an error. The caller adopts that owner before handling the error. It retains and retries the same real cleanup before creating a replacement. A cleanup failure never discards the original descriptors or turns their path into a new ownership record.
