# Native helper identity after NoDump

A trusted helper sets its own Linux dumpability to zero before it reads private material. That also prevents a same-account outside process from reading several peer procfs magic links. Startup cannot rely on a later peer executable or namespace symlink read.

The closed native startup hello transfers the actual helper-opened executable and user and cgroup namespace descriptors on the same physical control line. The canonical ancillary decoder binds them to the current kernel sender. The original outside launcher additionally binds that sender to its retained child creation handle or first authenticated native exec activation. Public code and namespace handles precede the separate private operation loan.

The private handoff gate compares the same held executable object, native namespace types and identity, literal helper command, current sender, creation lifetime and actual unit membership and cap. Neither public correlation fields, a pathname, account ownership nor a success callback can replace those observations. Dumpability remains zero.

The ordinary one-descriptor carrier limit is unchanged. Only the closed native constructor permits at most three roles; typed hello and operation consumers check their exact shapes. A claimed operation retains its current frame credentials for the same-frame native acknowledgement. The next frame resets them. Read-only observers have no operation-loan path.

The auxiliary helper uses the same identity path before receiving its original operation, holder and saved-disk roles. Native code and namespace tests exercise an actual protected child and native carrier only. They do not create a sandbox, namespace factory, artifact receipt or hardware boot grant. Full native startup and hostile handoff validation remain required.
