# Physical gVisor probe

The ordinary capability request reports construction facts. It can say that
the registered gVisor implementation can be prepared on this architecture and
kernel. It cannot say that an installed runtime has physically started.

After delivering its original signed runtime selection, the client can send
that exact manifest in the optional `runtime` field of `sandbox.probe` on the
same connection. The host matches the connection's retained successful
delivery receipt. A supplied manifest or installed-runtime list cannot create
that receipt.

The host then owns a separate private diagnostic purpose. It retains the
original runtime descriptors, native account and storage domain. A new private
temporary directory and checked native lease hold the probe's own runtime
files. This purpose creates no primary session manifest, session operation,
boot Need, startup token or stop capability. A real New can retain its existing
operation while probing; the diagnostic cannot issue or consume that operation.

The smoke command runs `/usr/bin/true` as virtual UID and GID 1000 through the
same patched signed companion closure, captured mounts and dedicated namespace
purpose as a real start. Physical readiness requires that command to finish
successfully. The original private PID 1 owns its descendants.

Cancellation stops that same native owner. A logical wait error retains the
creation pidfd and resource descriptors. Cleanup joins actual native exit
before releasing the delivery receipt or removing the probe's owned files.
A deadline or socket EOF cannot substitute for that exit evidence.

The generic request remains useful before runtime delivery. Its construction
result stays separate from physical readiness, and neither result grants a
session boot or replaces the checks at an actual start.
