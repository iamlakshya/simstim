# Original image checks during resume

A client-issued resume or restore rechecks its retained original image under the laptop policy before fetching values. Its closed expected-image projection contains the immutable image pins and optional saved-host identity. It is comparison data and cannot select another image or create native authority.

The host reads the protected VM Need through the same original primary operation before any stop or change, then checks again after the old holder's final publication. A supplied projection must exactly match the original image. Host display rows, mutable registry tags and current inventory cannot replace it. A provided projection on another wall is refused. The versioned feature is advertised only with this actual comparison route.

Offline automatic restore retains the original protected Need, accepted restore intent and last delivered policy and binding. It cannot observe untransmitted laptop configuration and does not contact the laptop to obtain it. An absent expected-image field does not rewrite that source. Existing native artifact, digest, advisory and prepare gates still apply.

The protected-operation regression uses actual native OP file ownership. Its metadata fixtures are not execution grants or a hardware restore proof.
