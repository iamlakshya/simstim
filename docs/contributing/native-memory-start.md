# Native memory at the start boundary

The outside creator checks the original supervisor's native cgroup before it lends the session operation or sends private start values. The process must inhabit its exact canonical cgroup v2 unit. That unit's `memory.max` must equal the complete declared reservation. Its `memory.swap.max` must be zero. The check runs again before readiness is accepted.

Manager properties and a manifest do not replace this kernel observation. The creator retains the original supervisor process and its lifetime handle throughout the check. A missing unit, a different cap or a different placement refuses the start before private boot rights are sent.

The direct path without a user manager does not yet create a canonical capped cgroup. It therefore cannot pass this boundary for a walled session. A direct cgroup producer remains required before that path is complete.

Source tests cover exact caps, understated reservations, swap and foreign placement. They do not establish native cgroup enforcement. Linux execution, cancellation and independent review remain separate gates.
