# Retained purge origin

A temporary attempt captures its origin before any session preparation. The factory requires the actual purge owner and its already-pinned roots. It retains the current process's kernel-mapped code, original root descriptors and original host and control sentinels. It records no permission to stop or remove a resource.

The same actual context registers each newly produced ordinary capture with its original operation. Registration checks the current holder, native ownership and root scope. A later native-only stopped check must find that exact object and operation in this retained origin. It still checks the original holder description, main and holder exits, completion object and any managed unit. The retained origin replaces only the named installation and root lookup that cannot succeed after deliberate cleanup.

A missing pathname is unknown. A retained object may survive its own deletion only when its actual native link count is zero and its original descriptor still identifies that same object. A renamed but linked object does not pass. If the original path names a replacement, the check refuses and preserves it. Saved phases, removal reports and copied root references supply none of these facts.

The factory's context is private to the real attempt. Existing ordinary callers keep the current named-origin checks. Closing the retained origin requires its registered actual captures and original operation descriptions to have closed first. It then closes only its own read-only descriptors.

The temporary child and whole transaction still need to use this factory before capture. Walled retained-origin registration and native caller admission remain separate work. These checks cannot construct a stopped subject or restore custody after a producer has disappeared. Source tests distinguish a real original unlink, a rename and a replacement. Real complete-attempt acceptance remains unproved.
