# The ordinary holder's purge decision

The original purge transaction can lend its native decision pair to an ordinary holder before it pauses the main process. The holder accepts both descriptors only from its authenticated original peer, on the same request continuation. It retains the actual socket identities and native roles. The acknowledgement means those same native descriptors have been installed. It does not grant stop permission.

A bound holder observes the first queued packet without consuming it. Commit is byte 1; abort is byte 2. Parent death, EOF and restoration first propose abort, then follow the actual first packet. If commit won, the holder keeps its pause and joins its real main process, PTY and shadow terminal. It writes the existing native join receipt. If abort won, it restores its own original pause and writes the restoration receipt. An unknown packet or native error retains the holder and its original handles.

A stream commit cannot arm or decide a bound holder. The parent retains the same loan through partial admission and until the actual restoration or stopped producer has joined. The old ordinary stopped checks still require their original physical completion and process exit facts.

This participant is an internal prerequisite. The transaction still needs the opaque global permit, every managed and Root monitor on the same pair, final work checks and every reader's physical join before it can queue commit. This change alone does not activate the public removal route.

The restoration receipt is written after the actual request reader and peer watcher have joined and both native decision descriptors have closed. A bound monitor which has not yet paused still follows this path. Closing an unused capture cannot skip its native cohort join.
