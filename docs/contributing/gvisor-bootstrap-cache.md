# Physical runtime cache closure

A successful physical userspace-kernel probe records the exact signed runtime companion closure, the mapped Go helper and the separately captured native C launcher. The code records include their bytes, native device and inode, mode, owner, size and change times. Boot, kernel and the original native host domain are also part of the key.

The probe retains those actual code descriptors. Command construction duplicates the same held objects and never reopens their paths after key construction. It rechecks them before native creation, after the physical probe and at cache publication. An installation change, changed C bytes or an uncertain observation requires a fresh physical probe. The existing wall cache remains the single publication store.

Every actual userspace-kernel boot, including a manual restart or automatic restore, freshly captures its own code closure and requires an exact matching physical fact before its native command is constructed. These facts supply diagnostic reuse only. The original operation, runtime selection, native boot loan, confinement and memory admission remain required. This does not establish the later trusted topology and private-payload boundary or native availability.
