# Original native whole-stop ownership

A physical removal first needs a genuine whole-stop source. Work-loss permission is a separate decision. A PID, stopped status, pulled-commit list, control acknowledgement, EOF or timeout cannot supply native closure.

The supported current path retains the same original primary operation and connects to the actual current managed supervisor. Its current native sender, mapped helper and namespace descriptors, native process handle, exact manager invocation, capped cgroup and already-owned holder description are checked. The holder proof observes the actual sender's existing exclusive kernel open-file-description lock. It is never created by a copied name or a new lock attempt.

The live helper accepts a stop only on that same original inspected connection. The outside owner independently waits for its native process handle, the same original cgroup to become empty or be removed, and both ordinary and auxiliary canonical units and cgroups to be absent. An ordinary file containing an empty-looking population value is refused.

After physical closure, the old transferred holder description closes and a new actual holder vacancy is acquired under the still-held original primary operation. The opaque stopped-session owner retains that operation identity, root and native observations for the consumer. Check requires the same operation. Close releases its own native resources and never closes the external operation.

Unknown current-boot sessions without the actual supported live owner, unmanaged sessions and orphan auxiliary lifetimes are preserved and refused. A lost native source remains unresolved and retained. No timeout releases its source or accounting ownership.

The source tests cover data-only and ordinary-file refusal. Actual managed stop, cancellation, manager loss, descendant cleanup and removal races still need native tests. This source change does not itself remove a session, waive local review or implement a warm or cold resume-preparation grant.
